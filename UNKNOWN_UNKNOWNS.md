# Unknown Unknowns and Risks

1. AI Studio dependency compatibility: prove Room, Ktor, MCP SDK in its single module.
2. Protocol/client variance: negotiate and maintain a tested matrix.
3. Network topology: Wi-Fi isolation may make VPN or bridge standard.
4. Android/OEM killing: design restartable visible service, not daemon promises.
5. FTS5/tokenizer: test selected driver with Hebrew and code.
6. SAF traversal performance/provider differences: benchmark, cancel, resume.
7. Git metadata: SAF may not provide efficient `.git`; optional companion/import.
8. Embeddings: license, APK/model size, RAM, multilingual/code quality, index scale.
9. Concurrent agents: transactions do not settle semantic authority; use proposals/conflicts/version checks.
10. Backup privacy: Auto Backup exclusion, encryption, key recovery, passphrase loss.
11. Tool selection: too many tools confuse agents; keep API compact.
12. Memory poisoning: authentication alone is insufficient; evidence/authority/approval/rollback.
13. Context budget: tokenizers differ; use chars/items and optional client token estimate.
14. Summary drift: regenerate from pinned evidence, retain derivation.
15. Deletion/privacy: define explicit irreversible purge apart from normal history.

## Decision checkpoints

- After Phase 0: embedded MCP viable?
- After Phase 2: SAF performance acceptable?
- After Phase 3: lexical baseline good enough?
- After Phase 5: direct Android HTTP works for every client?
- After evaluation: embeddings worth shipping?
- Before release: restore and credential-loss recovery proven?
